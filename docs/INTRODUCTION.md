# ApiGateKeeper —— 轻量 API 网关

## 一句话定位

ApiGateKeeper 是一个构建在 **FRAMPP**（FrankenPHP + caddy-access-filter +
Souin）之上的轻量 API 网关：装上即透明转发，边跑边沉淀 API 与客户端清单，
再用纯 PHP 规则引擎逐步加上缓存、限流、认证、黑名单等治理能力。

## 目标

- **零配置可用**：先当标准反向代理用起来，不配规则也不挡流量；访问过的 URL
  自动登记，后续治理有据可依。
- **先观察、后治理**：网关自动记录请求/响应元数据并沉淀统计，管理员"看着数据
  配规则"，而不是上来就写一堆配置。
- **轻量可维护**：核心治理逻辑全部由 PHP worker 实现、零 Composer 依赖；
  部署不复制代码，只挂一个 Caddy 片段；首次访问管理端由安装向导初始化，
  适合资源有限的小团队。
- **一体化交付**：网关转发、规则引擎、管理界面、Prometheus 指标、后台统计
  导入在同一个 FRAMPP 进程体系内完成。

## 功能

- **多应用模型**：按 base_path / Host / 自定义请求头把流量分到不同应用；每个
  应用有独立的"缺省放行 / 缺省缓存 / 自动加入"策略；未命中任何应用返回 404。
- **透明代理与动态上游**：默认透传；应用级上游组支持轮询与主备切换、主动/被动
  健康检查、缺省前缀映射，以及未配置时的统一兜底上游。
- **记录与统计**：热路径只追加 JSON 日志（不碰数据库），后台每分钟导入并聚合；
  自动生成 API / 客户端清单、请求趋势；仪表盘实时刷新。
- **规则引擎（access / filter 两阶段）**：
  - 缓存：force / no-cache / auto + TTL，配合 Souin HTTP 缓存
  - 限流：多维度组合（IP / 用户 / 参数…）、突发额度、超限自动拉黑
  - 认证：JWT / 不透明令牌（按应用隔离）
  - 黑名单：按 IP / 用户 / API Key / 请求参数维度
  - 变量系统：声明"按 key + TTL"的关联变量，跨请求联动（如记住上次访问、
    登录后保存令牌）
  - 动态改目标：按规则切换上游组、改写路径/请求头
  - 响应加工：替换 JSON 属性、把响应字段存成变量、JSON ↔ XML 转换，
    形成"响应 → 变量 → 后续许可"的闭环
- **管理端 SPA**：安装向导 + 账号密码登录；仪表盘（概览/监控/系统）；
  应用详情下管理 API 清单、客户端、规则、变量、缺省设置、上游、黑名单。
- **可观测**：Prometheus 指标（请求量、错误、拦截、延迟直方图、上游健康）
  通过 `/admin/api/metrics` 暴露。
- **部署形态灵活**：可挂进已有 FRAMPP（推荐，复用其启停）、独立 systemd 服务，
  或 Docker Compose 本地起环境。

## 适用场景

- **"先跑起来、再逐步治理"的 API 前置**：初期只要透明代理和访问记录，后期按需
  开缓存/限流/鉴权，不需要一次性设计完整策略。
- **上游服务治理**：为内部或对外 HTTP 服务统一入口，做限流防刷、认证校验、
  黑白名单、响应缓存与加工。
- **已有 FRAMPP / FrankenPHP 环境的团队**：不引入额外运行时，直接用同一套
  PHP 与启动体系。
- **业务需要"请求间关联"的接口**：比如换票码、一次性许可、登录响应里保存令牌
  供后续接口校验等"先授权后放行"的流程。
- **中小规模、单机或少量实例部署**：SQLite + APCu 的方案简单可控；管理、统计、
  指标都在本地闭环。

## 边界（说明）

ApiGateKeeper 面向轻量场景：当前共享状态基于单机 APCu（多实例迁 Redis 暂缓）、
access 阶段不读请求体、流式响应（SSE）不做阻断式后处理。高并发大规模集群、
复杂多租户编排等需求建议评估 Kong/APISIX 等重量级方案。
