# S15 规则级动态路由与路径改写

> 状态：已完成

## 1. 场景描述

按规则把不同 API 路由到不同上游组，并做路径改写（剥离 base_path / 前缀替换 /
加前缀）与请求头注入；未配规则的 API 走应用默认上游组的缺省映射。

## 2. 现状分析

- change_target 规则：upstream（按组名选组）/ rewrite_path / strip_prefix /
  set_headers（[RuleEngine.php](../../processor/src/RuleEngine.php:160)）。
- 上游组缺省映射：strip / replace / add（[Upstream.php](../../processor/src/Upstream.php:124)），
  规则 rewrite 优先于组缺省映射。
- 每个应用可有多个上游组，access 输出目标地址供 Caddy 转发。
- 管理 UI：上游页（组/映射）+ 规则页（change_target）。

## 3. 设置方法

```bash
# 订单组与旧版组
POST /admin/api/apps/{appId}/upstreams {"name":"订单新组","strategy":"round_robin","path_mode":"replace","prefix_from":"/v1","prefix_to":"/api/v1"}
POST /admin/api/apps/{appId}/upstreams {"name":"订单旧组","strategy":"active_standby","path_mode":"strip"}

# /v1/orders/* 走"订单旧组"且注入头
POST /admin/api/apps/{appId}/rules
  {"name":"订单走旧组","api_pattern":"GET /orders/*","client_pattern":"*",
   "action_type":"change_target","phase":"access","scope":"app",
   "params":{"upstream":"订单旧组","strip_prefix":1,
             "set_headers":{"X-App":"orders"}}}
```

## 4. 测试方法

### 自动化

```bash
php processor/tests/run.php
```

覆盖：test_upstream_backend_by_name、test_upstream_map_path（strip/replace/add
与规则优先）。

### 手工

1. 建两个 mock 上游与两个上游组，各自返回不同标识。
2. 配 change_target 把 `GET /orders/*` 指向 B 组 → 请求落到 B 后端。
3. 未配规则的路径落到默认上游组；检查路径按 strip/replace 改写。
4. `X-App: orders` 请求头出现在上游请求中。
