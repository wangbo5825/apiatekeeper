# S16 按租户/地域动态路由

> 状态：未完成

## 1. 场景描述

同一 API 根据请求上下文（tenant-id / region 等 header 或 query 参数）动态选择
上游：多租户各自的后端集群、按地区就近路由、灰度租户走新版本。

## 2. 现状分析

- 已具备：多上游组 + 缺省映射；规则级 change_target 可切换组；变量系统可按
  header/query 解析值。
- **缺口**：change_target 的 `upstream` 参数目前是静态字符串
  （`$route['backend'] = (string) $params['upstream']`），不经过变量解析，
  无法按请求内容选择组名。

## 3. 设置方法（规划方案，待实现）

目标：把 change_target 的 upstream 改为支持变量引用
（如 `var:tenant_group` 或 `req.header:X-Tenant` 经映射表查组名）。

```json
{
  "name": "租户路由",
  "api_pattern": "*",
  "action_type": "change_target",
  "params": {
    "upstream": "var:tenant_group",
    "rewrite_path": "strip:base"
  }
}
```

可配合声明变量：tenant_group 由"维度 req.header:X-Tenant → 组名映射"写入。

## 4. 测试方法（验收标准，待实现）

1. 两个上游组 A/B；header `X-Tenant: t1` 请求应落在 A，`t2` 落在 B。
2. 缺失 header → 走默认组（或按策略拒绝）。
3. 组名不存在/组无健康目标 → 明确降级（默认组或 502），不 panic。
4. 单元测试：变量解析后的 resolve('B') 命中 B 组（参考
   test_upstream_backend_by_name 扩展）。
