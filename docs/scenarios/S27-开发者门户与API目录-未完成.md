# S27 开发者门户与 API 目录

> 状态：未完成

## 1. 场景描述

基于网关自动沉淀的 API 清单，向调用方提供只读目录：接口路径/方法、认证要求、
限流配额、示例与实时状态；调用方自助申请密钥后接入。适合把网关"从运维工具"
升级为"API 产品入口"。

## 2. 现状分析

- **未实现**：管理端 SPA 面向管理员，无面向调用方的目录/自助页。
- 可复用基础：
  - apis 清单自动登记 + 各 API 统计（S02）是目录数据源；
  - 规则元数据（auth/rate_limit 等）可翻译为"该 API 的接入要求"；
  - 管理 REST 可加只读公开端点，令牌发放可复用 tokens/生命周期接口（S10）。

## 3. 设置方法（规划方案，待实现）

规划：

1. 公开只读接口：
   `GET /public/catalog`（按应用/版本返回 API 列表 + 接入要求 + 状态）。
2. 自助申请：调用方表单 → 管理员审批 → 生成 key（对接 S07/S10）。
3. 调用方可查看自己的用量（隔离的统计查询，如 client_key 维度）。
4. 可选 OpenAPI 导出：由 apis 清单 + 模板生成 swagger/openapi.json。

## 4. 测试方法（验收标准，待实现）

1. 自动登记一批 API 后目录可见性与清单一致（方法/模板/名称）。
2. 带 auth/rate_limit 规则的 API 在目录中标注"需 Bearer/限流 100/min"。
3. 申请流程产生 key → 调用成功；调用方仅能查到自己用量。
4. OpenAPI 文件可被 Swagger UI 加载并校验。

## 5. 后续工作
