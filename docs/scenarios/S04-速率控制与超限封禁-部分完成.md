# S04 速率控制与超限封禁

> 状态：部分完成

## 1. 场景描述

控制客户端（IP / 用户 / API Key / 组合维度）对 API 的访问速率；超限返回 429；
可选自动拉黑（临时禁止），也可人工永久限制；进一步判定超限流量是否属于恶意
扫描。

## 2. 现状分析

### 已完成

- rate_limit 规则：固定窗口 + 突发额度（burst），维度 keys 支持
  `req.ip / req.userid / req.apikey / dim:user / req.query:* / var:*`
  多组合（[RateLimit.php](../../processor/src/RateLimit.php:20)）。
- 超限返回 429 + Retry-After（[RuleEngine.php](../../processor/src/RuleEngine.php:145)）。
- `auto_blacklist` 超限自动拉黑：APCu 立即生效 + 事件文件异步持久化
  （[Blacklist.php](../../processor/src/Blacklist.php:66)）。
- 黑名单管理：维度 req.ip / req.userid / req.apikey / 自定义 query，支持
  过期时间；不填过期时间即永久（管理 UI 显示"永久"）。
- 管理 UI：应用详情 → 规则（rate_limit 表单：窗口/阈值/突发/维度/自动拉黑），
  应用详情 → 黑名单。

### 未完成 / 缺口

- 自动拉黑维度硬编码为 req.ip：即使按 userid/apikey 限流，拉黑的是来源 IP。
- 自动拉黑没有"永久"档（只能设很长时长）；永久限制靠人工添加。
- 没有"恶意扫描判定"：只能判断量超限，不识别扫描特征（见 S05/S06/S19/S20）。
- 限流计数在 APCu，多实例部署各自计数。

## 3. 设置方法

管理 UI：应用详情 → 规则 → rate_limit。

等价 REST：

```bash
# 按 IP 限流：60s 内 100 次 + 突发 20；首次超限自动拉黑 1 小时
curl -s -X POST http://host/admin/api/apps/{appId}/rules \
  -H 'Content-Type: application/json' \
  -d '{"name":"按IP限流","api_pattern":"GET /api/*","client_pattern":"*",
       "action_type":"rate_limit","phase":"access","scope":"app",
       "params":{"window":60,"limit":100,"burst":20,
                 "keys":["req.ip"],"auto_blacklist":1,
                 "auto_blacklist_duration":3600}}'

# 永久限制：人工加入黑名单（不填 expires_at）
curl -s -X POST http://host/admin/api/apps/{appId}/blacklist \
  -H 'Content-Type: application/json' \
  -d '{"dimension":"req.ip","value":"1.2.3.4","reason":"滥用"}'
```

注意：黑名单需配合 blacklist 规则（声明维度）才生效，见 S11。

## 4. 测试方法

### 自动化 / E2E

`./test/e2e.sh` 含限流用例：窗口 60s、limit=2，第 3 次请求应返回 429。

### 手工

1. 配置 `{"window":60,"limit":2,"keys":["req.ip"],"auto_blacklist":1,
   "auto_blacklist_duration":60}`。
2. 同 IP 连续请求 3 次：前 2 次 200，第 3 次 429 且带 Retry-After。
3. 等待拉黑生效后即使窗口重置也返回 403（黑名单规则命中）；黑名单页出现
   source=自动、reason=auto rate-limit blacklist 的记录。
4. 手工加一条无过期时间的黑名单，确认界面显示"永久"且一直 403。

预期：429 → 临时 403 → 移除黑名单后恢复。
