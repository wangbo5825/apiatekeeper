# S18 请求签名与防重放

> 状态：未完成

## 1. 场景描述

服务间/敏感写接口使用请求签名（HMAC-SHA256 + 时间戳/随机数）防止请求被篡改
与重放；网关校验通过才转发，重复的 nonce/时间窗口外的请求直接拒绝。

## 2. 现状分析

- **未实现**：无 HMAC/签名校验规则，无 nonce 去重。
- 可复用基础：
  - auth 规则框架可扩展新 type（现 jwt/token 两分支）；
  - APCu + TTL 天然适合 nonce 去重（类似限流计数/变量槽）；
  - 变量/header 维度可解析 timestamp / nonce / signature。

## 3. 设置方法（规划方案，待实现）

目标规则参数：

```json
{
  "name": "签名校验",
  "api_pattern": "POST /webhook/*",
  "action_type": "auth",
  "params": {
    "type": "hmac",
    "secret_ref": "req.header:X-Service-Key",
    "header": "X-Signature",
    "timestamp_header": "X-Timestamp",
    "nonce_header": "X-Nonce",
    "clock_skew": 300,
    "algorithm": "sha256"
  }
}
```

实现要点：

1. 规范化待签串（method + path + query + body hash + timestamp + nonce）。
2. 验签失败/时间戳偏差超限 → 401/403。
3. nonce 写入 APCu（appId+key+nonce，TTL=窗口），重复 nonce → 拒绝。
4. access 契约暂无 body → 先支持不参与签名的请求，body 参与需契约升级
   （当前先以 headers/query/path 签名或声明 body_hash）。

## 4. 测试方法（验收标准，待实现）

1. 用已知密钥对同一请求签名 → 200；改任一 header/query → 401。
2. 重放完全相同请求（含同 nonce/时间戳）→ 第二次被拒。
3. 时间戳偏移超过 clock_skew → 拒绝。
4. 自动化：新增签名单测（构造/篡改/重放三例），并加 e2e 用例。
