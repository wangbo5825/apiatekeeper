# S22 规则影子模式（dry-run 试运行）

> 状态：未完成

## 1. 场景描述

新规则先以"只记录、不执行"的方式试运行：流量照常放行，但网关记录"如果启用会
拦截/改写多少请求、哪些调用方"，管理员看效果后决定是否真正启用。契合项目
"先观察、后治理"定位。

## 2. 现状分析

- **未实现**：规则没有 dry-run / shadow 开关；RuleEngine::evaluate 命中即执行
  deny/rewrite。
- 可复用基础：规则表已有 enabled 字段；deny 决策会走 recordDenied + Metrics；
  APCu 计数可累计"假想拦截"。

## 3. 设置方法（规划方案，待实现）

目标：

1. rules 表增加 `shadow`（或 enabled=2）语义：匹配照常，但不执行 deny / 路由
   改写，只把"假设结果"写入事件/计数。
2. 规则页提供"试运行"开关与效果摘要（命中数、涉及 IP/Top API）。
3. 记录建议：shadow 决策写 JSON 事件（类似 blacklist-events.log）由导入器落
   SQLite 或独立 shadow_events 表。

示例规则（规划）：

```json
{"name":"新限流(影子)","api_pattern":"GET /export/*",
 "action_type":"rate_limit",
 "params":{"window":60,"limit":10,"shadow":true}}
```

## 4. 测试方法（验收标准，待实现）

1. 开启影子：超限流量仍 200/正常转发。
2. 查看影子命中报表：应显示被拦数量与调用方清单。
3. 关闭影子（正式启用）→ 命中 429。
4. 自动化：evaluate 增加 shadow 分支单测，验证 deny 不返回但计数增加。

## 5. 后续工作

- 影子与真实决策的指标分开（`shadow_hits_total` 等）。
- 批量"试运行一组规则"的管理流程。
