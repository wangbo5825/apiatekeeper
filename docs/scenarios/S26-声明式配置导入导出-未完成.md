# S26 声明式配置导入导出与备份

> 状态：未完成

## 1. 场景描述

把应用及其全部配置（规则、上游、黑名单、变量、API 清单、设置）导出为
YAML/JSON 文件，可备份、进 git 评审、在另一环境一键导入（对标 Kong decK /
APISIX 声明式配置）。

## 2. 现状分析

- **未实现**：无导出/导入接口；配置仅存在 SQLite，通过管理 REST 逐条维护。
- 可复用基础：所有业务表结构清晰（apps/upstreams/apis/rules/variables/
  blacklist），AdminApi 有各资源 CRUD，可包装为整包导出/导入。
- Importer 只处理请求日志，不处理配置。

## 3. 设置方法（规划方案，待实现）

目标接口：

```text
GET  /admin/api/export            → 全量（含 meta 版本号）
GET  /admin/api/export/apps/{id}  → 单应用包
POST /admin/api/import            → 上传并校验后落库（整包或单应用）
```

校验规则：导入前先做现有校验（应用 base_path 冲突、API 模板冲突、规则类型
合法），可加 `dry_run: true` 只校验不落库。

## 4. 测试方法（验收标准，待实现）

1. 建一个含 2 应用 ×（规则/上游/黑名单/变量/API 清单）的库 → 导出。
2. 清库后导入 → 结构与行为一致（抽查规则命中、限流、路由结果）。
3. 导出文件固定顺序与幂等（重复导入不产生重复记录）。
4. 校验：故意改坏字段导入应返回 400 且库无变化（dry_run）。

## 5. 后续工作

- CLI 导入（对比 web 安装器安全风险，建议走命令行）。
