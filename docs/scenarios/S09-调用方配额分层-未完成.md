# S09 调用方配额分层（套餐化限流）

> 状态：未完成

## 1. 场景描述

把调用方分为不同套餐/等级，每档配额不同（如免费 100 次/分、付费 5000 次/分、
白名单不限）；按调用方身份查套餐后套用对应限流，并可返回剩余配额头。

## 2. 现状分析

- **未实现**：限流规则参数是静态值，无法按调用方动态取 limit/window。
- 已具备的基础：
  - rate_limit 的 keys 可按 `req.apikey / req.userid / dim:user` 计数；
  - 身份归一与 client_pattern 可表达调用方；
  - 缺的是"key/用户 → 套餐 → 限流参数"的映射与查找，以及配额剩余量输出。

## 3. 设置方法（规划方案，待实现）

目标配置形态：

```json
{
  "name": "套餐配额",
  "action_type": "rate_limit",
  "params": {
    "keys": ["dim:user"],
    "plan_source": "tiers",
    "plans": {
      "free":  {"window": 60, "limit": 100},
      "pro":   {"window": 60, "limit": 5000},
      "unlimited": {"unlimited": true}
    }
  }
}
```

实现建议：新增 tiers 表（dimension 值 → plan）；规则执行时按当前请求解析出的
维度值查 plan；429 同时返回 `X-RateLimit-Limit/Remaining`。

## 4. 测试方法（验收标准，待实现）

1. 同一 API 用两个 API Key（free / pro）各打 101 与 5001 次 → 分别 429。
2. unlimited 档在窗口内 10 万次不拦截。
3. 单元测试：plan 查询缓存与失效、窗口计数、响应头。
