# S25 超量告警与配额提醒

> 状态：未完成

## 1. 场景描述

客户端用量接近/超过配额时主动提醒或告警（而非静默等 429）：如用量达 80% 通知、
超量后告警、持续超量自动升级限制；为运营留出干预窗口。

## 2. 现状分析

- **未实现**：无配额定义与阈值提醒（S09 的套餐配额也未实现）。
- 可复用基础：
  - Prometheus 端点已有 app 级计数/错误/延迟，外部可挂告警规则；
  - 自动拉黑事件通道可承载"升级动作"；
  - 统计链路可作离线用量核对。

## 3. 设置方法（规划方案，待实现）

目标配置：

```json
{
  "name": "免费套餐用量提醒",
  "action_type": "quota_watch",
  "params": {
    "dimension": "req.apikey",
    "window": 86400,
    "limit": 10000,
    "warn_at": 0.8,
    "notify": "log|webhook",
    "escalate": {"after": 3, "action": "blacklist_1d"}
  }
}
```

建议：计数器沿用 RateLimit 的 APCu 槽位；warn/escalate 事件写事件文件由导入
器持久化；Prometheus 暴露 `gatekeeper_quota_usage_ratio`。

## 4. 测试方法（验收标准，待实现）

1. 把 limit 调小，用量过 80% → 产生 warn 事件（日志/事件文件）。
2. 连续 N 日/窗口超量 → escalate 动作触发（自动拉黑）。
3. 未超量客户端无事件；解除后恢复。
4. 自动化：窗口计数 + 阈值边界单测。
