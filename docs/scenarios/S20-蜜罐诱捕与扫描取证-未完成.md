# S20 蜜罐诱捕与扫描取证

> 状态：未完成

## 1. 场景描述

登记若干"不存在的诱饵路径"（/admin/backup.zip、/.env、/wp-login.php 等），
真实客户端不会访问；命中诱饵几乎可判定为扫描/探测，网关记录完整证据并对来源
自动拉黑或告警。

## 2. 现状分析

- **未实现**：无诱饵概念与"命中即拉黑"联动。
- 可复用基础：
  - API 清单 + default_allow=0 模式可让诱饵路径 404，但无法区分普通未登记
    路径与诱饵；
  - 自动拉黑持久化通道（Blacklist events）与记录通道（Recorder）现成。

## 3. 设置方法（规划方案，待实现）

目标：

1. 应用内新增"诱饵路径"列表（或规则标记 apis 条目 honeypot=1）。
2. access 命中诱饵：
   - 返回 404/403（与真实未登记响应一致，避免暴露）；
   - 记录证据行（来源 IP/UA/完整路径/时间）；
   - 可选自动拉黑（首次观察、短时拉黑；多次命中延长/永久）。

示意规则（规划）：

```json
{
  "name": "诱饵路径",
  "api_pattern": "GET /.env",
  "action_type": "honeypot",
  "params": {"response": 404, "blacklist_duration": 3600}
}
```

## 4. 测试方法（验收标准，待实现）

1. 配置诱饵后请求 `/.env` → 与未登记路径一致的 404，且不转发上游。
2. 查看证据记录（request_logs / 新 events 文件）含 UA 与来源。
3. 触发自动拉黑后同 IP 访问其它路径 403；解除后恢复。
4. 自动化：honeypot 单测 + e2e（诱饵 404 + 事件行存在）。
