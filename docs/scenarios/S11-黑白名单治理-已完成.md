# S11 黑白名单治理

> 状态：已完成

## 1. 场景描述

按维度（IP / 用户 / API Key / 请求参数值）维护黑名单与白名单：黑名单命中即
拦截（403）；白名单/清单模式只放行显式登记的 API。条目支持过期或永久，来源
区分人工与自动。

## 2. 现状分析

### 黑名单

- 条目：app 内 dimension + value + reason + expires_at + source
  （manual/auto），永久 = 不填过期（[Blacklist.php](../../processor/src/Blacklist.php:94)）。
- 规则 blacklist 声明维度后命中拦截；自动拉黑事件异步持久化
  （[Importer.php](../../processor/src/Importer.php:137)）。
- 管理 UI：应用详情 → 黑名单（增删、来源徽标、过期时间）。

### 白名单 / 清单放行

- 应用设置 default_allow=0 + auto_add_rules=0 → 严格白名单：仅 apis 表中
  登记的 API 放行，未登记 404（[Contract.php](../../processor/src/Contract.php:54)）。

## 3. 设置方法

管理 UI：

1. 应用详情 → 黑名单：加入维度值（`req.ip` / `req.userid` / `req.apikey` /
   `req.query:phone` 等）。
2. 应用详情 → 规则：新建 blacklist 规则声明拦截维度。
3. 应用详情 → 设置：default_allow 关、自动加入关 → 清单白名单模式。

等价 REST：

```bash
curl -s -X POST http://host/admin/api/apps/{appId}/blacklist \
  -H 'Content-Type: application/json' \
  -d '{"dimension":"req.ip","value":"203.0.113.9","reason":"扫描"}'

curl -s -X POST http://host/admin/api/apps/{appId}/rules \
  -H 'Content-Type: application/json' \
  -d '{"name":"黑名单","api_pattern":"*","client_pattern":"*",
       "action_type":"blacklist","phase":"access","scope":"app",
       "params":{"dimensions":["req.ip"]}}'
```

## 4. 测试方法

### 自动化 / E2E

`./test/e2e.sh` 黑名单用例：加入 127.0.0.1 + blacklist 规则后访问返回 403；
删除后恢复。

### 手工

1. 加黑名单条目 + 规则 → 命中 403（仅加条目不生效，需规则声明维度）。
2. 永久条目不填 expires_at → UI 显示"永久"。
3. 白名单模式：default_allow=0 后未登记 API 404，登记后 200。
