# S14 响应契约适配（字段替换/JSON↔XML/脱敏）

> 状态：已完成

## 1. 场景描述

上游响应与客户端期望不一致时，由网关做契约适配：

- 替换/裁剪响应 JSON 字段（老字段名 → 新字段名、脱敏敏感字段）；
- JSON ↔ XML 互转（老客户端要 XML，新后端给 JSON）；
- 把响应字段存为变量供后续请求使用（见 S13）。

## 2. 现状分析

- response_transform 规则（filter 阶段）支持 op = replace / save_variable /
  convert，buffer 模式下生效，自动更新 Content-Type
  （[ResponseTransformer.php](../../processor/src/ResponseTransformer.php)）。
- 规则可按 API 绑定，多规则按优先级顺序执行；stream 模式（SSE）不加工仅记录。
- 管理 UI：应用详情 → 规则 → response_transform 表单。

## 3. 设置方法

管理 UI：应用详情 → 规则 → 新建规则，规则类型选 response_transform
（执行阶段为 filter，即收到上游响应之后）。

等价 REST：

```bash
# 字段重命名/脱敏：把 data.phone 替换为掩码
POST /admin/api/apps/{appId}/rules
  {"name":"手机号脱敏","api_pattern":"GET /users/{id}",
   "action_type":"response_transform","phase":"filter","scope":"app",
   "params":{"op":"replace","path":"data.phone","value":"138****5678"}}

# JSON → XML
POST /admin/api/apps/{appId}/rules
  {"name":"转XML","api_pattern":"GET /legacy/*",
   "action_type":"response_transform","phase":"filter","scope":"app",
   "params":{"op":"convert","format":"json_to_xml","root":"response"}}
```

## 4. 测试方法

### 自动化

```bash
php processor/tests/run.php
```

覆盖 response_test.php（replace / save_variable / convert 与非法 body 透传）。

### 手工 / E2E

1. 配 replace 规则后请求对应 API：响应字段被替换且仍为合法 JSON。
2. 配 convert 规则后请求：返回 application/xml，body 可被 XML 解析。
3. stream 路由（如 /sse）确认不改 body。
4. 非法 JSON body：确认按透传策略返回原始响应。
