# S08 多级授权与调用方细粒度控制

> 状态：部分完成

## 1. 场景描述

在"认证通过"之后再按调用方做授权：只允许特定 IP/网段、特定用户、特定 API Key
访问某个 API；规则可绑定到具体 API，形成 API × 调用方的访问矩阵。

## 2. 现状分析

### 已完成

- 每条规则都有 `client_pattern`，支持 `*`、`ip:x.x.x.x`、`ip:cidr`、
  `key:xxx`、`user:xxx`、逗号多选（[Identity.php](../../processor/src/Identity.php:39)）；
  它决定规则作用于哪些调用方。
- 规则可绑 API 级（scope=api + api_id）或应用级，匹配排序按"API 具体度 >
  客户端具体度 > priority"（[RuleEngine.php](../../processor/src/RuleEngine.php:66)）。
- 对未授权命中可以 403（blacklist/variable_check）或 404（清单外）。
- 管理 UI：规则表单含"客户端"输入框；API 列表与规则列表均在应用详情页。

### 未完成 / 缺口

- 无 JWT scope/claim 条件（如 `scope=read:orders`），只有身份维度的匹配。
- client_pattern 不支持取反（如 `!ip:10.0.0.0/8`），无法用单条规则表达
  "除内网外全部拒绝"的纯白名单；这类边界需在 Caddyfile 层用 `remote_ip`
  匹配器实现（见 S12），或先按具体调用方逐个拒绝。
- 无"应用默认拒绝 + 按调用方显式允许"的 ACL 表，需要组合规则/清单实现。

## 3. 设置方法

管理 UI：应用详情 → 规则 → 新建/编辑，填"客户端"（如 `ip:10.0.0.0/8`）。

等价 REST：

```bash
# 把某类调用方排除在 API 之外：阻断 user:scanner 访问 /export
curl -s -X POST http://host/admin/api/apps/{appId}/rules \
  -H 'Content-Type: application/json' \
  -d '{"name":"屏蔽扫描者","api_pattern":"GET /export/*",
       "client_pattern":"user:scanner","action_type":"blacklist",
       "phase":"access","scope":"app","params":{"dimensions":["req.ip"]}}'
```

说明：blacklist 规则 + client_pattern = "只对匹配到的调用方拒绝"；
API 级规则 + `key:xxx` / `user:xxx` 可让限流/认证等只作用于特定调用方。
"仅允许特定调用方、其余全部拒绝"目前需要 Caddy 层 IP 匹配或逐调用方拒绝，
或等 ACL/取反语义实现（见第 5 节）。

## 4. 测试方法

1. 对某 API 配 blacklist 规则，client_pattern 设为 `user:scanner`。
2. 以 scanner 身份请求 → 403；其它用户请求 → 正常放行。
3. 反向验证：client_pattern 只做命中，不做排除（把规则 client_pattern 改成
   `ip:10.0.0.0/8` 时，被 403 的是 10.x 来源而非其它来源）。
4. 自动化：rules_test / ruleengine_test 覆盖 pattern 匹配（user/key/ip/CIDR）。

预期：不同调用方对同一 API 的放行/拒绝符合 client_pattern。

## 5. 后续工作

- auth 解码结果携带 claims，规则支持 `require_claim` / `require_scope`。
- client_pattern 支持 `!` 取反，或提供显式 ACL（应用 → API → 调用方允许列表）
  管理面，才能表达真正的"仅限白名单"授权。
