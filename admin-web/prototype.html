API Gatekeeper 模型：请求先命中应用（未命中 → 404）。每个应用有统一缺省配置： 缺省放行 / 缺省缓存与 TTL / 自动加入规则。正常缺省 = 放行 + 自动加入： 新接口自动访问指定上游，并按 URL 模式自动加入 API 列表——零配置即可使用， 直接获得全部可用 API 列表。关闭自动加入后，新 API 不再入列。

维度定义（key 的来源） 新增

标准维度（内置）

req.ip / req.url / req.method —— 请求中必然可解析

参数化维度（声明时写死参数名）

req.query:<name> / req.header:<name> / req.path:<name>，如 req.query:uid

语义维度（解析链，解决字段名不统一）

维度名解析链（按顺序取第一个非空）操作
dim:userreq.userid → req.header:X-User-Id → req.query:uid
dim:devicereq.header:X-Device-Id → req.query:device_id
变量 key 维度与 rate_limit 维度都可引用维度定义（如 dim:user）；解析链全部缺失时变量视为不存在。
